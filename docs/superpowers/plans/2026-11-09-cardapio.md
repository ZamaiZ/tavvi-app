# Cardápio Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan inline, task by task. Checkboxes are the progress record.

**Goal:** Build secure, responsive cardápio management, batch authoring, publication, and public menu rendering in `tavvi-app`.

**Architecture:** Keep reads in Server Components and the menu DAL; keep every mutation behind validated Panel Server Actions and transactional Postgres RPCs. A shared client workspace presents Índice, Quadro, and mobile list views over one menu DTO. The public slug route receives a separate narrow menu DTO only when the restaurant is active and the menu is published.

**Tech Stack:** Next.js 16.4.2 App Router, React 19, Supabase/Postgres/RLS/Storage, Zod, shadcn + Tailwind, `motion/react`, `@dnd-kit/*`, IndexedDB, and `mediabunny` for browser media preparation.

**Spec:** [2026-11-09-cardapio-design.md](../specs/2026-11-09-cardapio-design.md)

## Global Constraints

- Use the current app’s shadcn + Tailwind tokens; no custom Panel feature stylesheet and no legacy CSS.
- Keep public presentation (`immersive`, `catalog-list`, `catalog-grid`) separate from editor views.
- Do not couple `restaurants.status` to menu publication.
- Every action authenticates, authorizes the active restaurant, and validates untrusted input; RLS/RPC also enforce ownership and invariants.
- Storage bytes upload directly from the browser using short-lived signed authorization; server actions receive metadata only.
- No `git`, test, `typecheck`, `build`, or `lint` command may be run. Use source/SQL review only and state this limit clearly.
- Next 16 local Server Actions and Server/Client Component guides were read before implementation.

## Review Focus

- A forged category/item/media ID from another restaurant must not mutate or expose that restaurant’s data.
- Hiding, deleting, moving, or removing media from the final eligible public item must not leave a published menu empty.
- A stale or invalid batch draft, duplicate row, or IndexedDB quota failure must not silently discard the active form.
- MIME, byte size, video duration, object path, and orphan cleanup must be constrained across browser, action, Storage, and database boundaries.
- DnD and every reorder/move action must remain keyboard/touch accessible and usable with reduced motion and at the mobile dock/safe area.
